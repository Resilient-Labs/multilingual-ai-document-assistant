# ACCESSIBILITY AUDIT — 2026-03-28-1504
## Scope: Full Project — WCAG 2.1 AA Compliance

Audited paths: `app/page.tsx`, `app/layout.tsx`, `app/dashboard/page.tsx`, `app/translate/[id]/page.tsx`, `app/document/[id]/page.tsx`, `components/upload-form.tsx`, `components/shared/LanguageSelector.tsx`, `components/features/**/*`, and representative `components/ui/*` primitives used by those surfaces (tabs, dialog, select, button, alert, spinner, sonner, radio-group, item).

---

### High Severity (blocks users with disabilities)

1. **Keyboard cannot use inner “Browse files” / “Take photo” buttons to open the file picker**  
   - **Where:** `components/upload-form.tsx` — `<Button type="button">` nested inside the `react-dropzone` root (`getRootProps()`).  
   - **WCAG:** [2.1.1 Keyboard](https://www.w3.org/WAI/WCAG21/Understanding/keyboard.html) (Level A).  
   - **Issue:** Pointer users may still open the dialog via bubbling to the parent, but when focus is on the inner `button`, **Enter/Space activate only the button**, which has no `onClick` tied to the hidden file input. Keyboard users may believe the control is broken.  
   - **Fix pattern:** Either (a) merge `getInputProps()` onto the visible button (`asChild` + `<label htmlFor={inputId}>` wrapping the button, with `input` `id` matching), or (b) add `onClick`/`onKeyDown` on the button that calls `open()` from `useDropzone` (if using `useDropzone({ noClick: true })` on the root), or (c) use a single `<label>` styled as a button linked to the hidden input. Ensure one clear tab stop and documented keyboard shortcut in copy if needed.

2. **Submit control loses its accessible name and live status text during upload/OCR**  
   - **Where:** `components/upload-form.tsx` — submit `<Button>` renders `{isSubmitting ? <Spinner /> : submitLabel}`; when `isSubmitting` is true, visible text (`submitLabel` / `ocrProgress`) is not rendered alongside the spinner.  
   - **WCAG:** [2.4.6 Headings and Labels](https://www.w3.org/WAI/WCAG21/Understanding/headings-and-labels.html) (AA), [4.1.3 Status Messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html) (AA).  
   - **Issue:** Sighted users lose the progress string; screen reader users may only hear the spinner’s generic label unless overridden. Dynamic OCR phases (“Recognizing… N%”) are not reliably exposed.  
   - **Fix pattern:** Keep **visible** progress text next to or under the spinner (e.g. `aria-busy="true"` on the button, inner flex with `Spinner` + `<span aria-live="polite">` for `ocrProgress`). Optionally `aria-label` on the button combining action + current phase. Do not replace the only text label with a spinner alone.

### Medium Severity (degrades experience)

3. **No mechanism to bypass repeated blocks of content**  
   - **Where:** `app/layout.tsx` (global); no skip link on home, translate, or document flows.  
   - **WCAG:** [2.4.1 Bypass Blocks](https://www.w3.org/WAI/WCAG21/Understanding/bypass-blocks.html) (Level A).  
   - **Fix pattern:** Add a first-focusable **skip link** (`<a href="#main-content" className="sr-only focus:not-sr-only …">Skip to main content</a>`) in the root layout and `id="main-content"` on each page’s primary `<main>`.

4. **Page titles are not unique or descriptive per view where context differs**  
   - **Where:** `app/layout.tsx` sets static `title: "AI Document Translator"`. `app/translate/[id]/page.tsx` is a client page with **no** `generateMetadata`. `app/dashboard/page.tsx` has no metadata.  
   - **WCAG:** [2.4.2 Page Titled](https://www.w3.org/WAI/WCAG21/Understanding/page-titled.html) (Level A).  
   - **Fix pattern:** For translate: add a small server `layout.tsx` or wrapper route with `generateMetadata` using the `id` (and optional sanitized filename from session if available server-side). For dashboard: export `metadata` or `generateMetadata`. Pattern: `title: \`${context} | AI Document Translator\``.

5. **Document view lacks a main landmark**  
   - **Where:** `app/document/[id]/page.tsx` — top-level `<div>` columns only.  
   - **WCAG:** [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html) (Level A).  
   - **Fix pattern:** Wrap primary content in `<main>` (one per page), optionally with `aria-labelledby` pointing at the panel heading.

6. **Dashboard: placeholder chrome is not structured with headings**  
   - **Where:** `app/dashboard/page.tsx` — mobile header uses `<span>` for title/type; desktop header is plain text in `<header>`.  
   - **WCAG:** [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html).  
   - **Fix pattern:** Use `<h1>` (document title) and `<h2>`/`<h3>` for sections; keep visual styling via classes.

7. **Detect tab: section labels are styled as text, not headings**  
   - **Where:** `components/features/detect/DetectTab.tsx` — “Suggested Next Steps” and “Helpful Resources” use `<div className="text-lg font-semibold">`.  
   - **WCAG:** [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html).  
   - **Fix pattern:** Use `<h2>` or `<h3>` (matching outline order) with the same classes.

8. **Decorative Lucide icons may be exposed as unlabeled graphics**  
   - **Where:** `DetectTab.tsx` — `OctagonAlertIcon`, `Clock4Icon`, `ShieldAlertIcon`, `ExternalLinkIcon` in `ItemMedia` / `Badge` / `ItemActions` without `aria-hidden="true"`. Similar pattern in `app/translate/[id]/page.tsx` for `ArrowLeftIcon` / `ArrowRightIcon` next to text (arrow beside filename flow may be decorative).  
   - **WCAG:** [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG21/Understanding/non-text-content.html).  
   - **Fix pattern:** Add `aria-hidden="true"` to icons that duplicate adjacent text; if an icon is the **only** affordance, give the control an `aria-label` instead.

9. **Upload error container uses `role="alert"` + `aria-live="assertive"` even when empty**  
   - **Where:** `components/upload-form.tsx` — `ErrorMessage` always renders the live region; children are `{error ?? ""}`.  
   - **WCAG:** [4.1.3 Status Messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html) (use assertive only for urgent/interrupting errors).  
   - **Fix pattern:** Render the live region **only when `error` is non-null**, or use `aria-live="polite"` on a dedicated status element; keep `role="alert"` only for active errors.

10. **Translation loading / TTS loading not announced as status messages**  
    - **Where:** `app/translate/[id]/page.tsx` — spinners for loading session and translation have `aria-label` on the spinner, but there is no **`aria-live`** region announcing phase changes (e.g. “Translating…”, “Generating audio…”).  
    - **WCAG:** [4.1.3 Status Messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html).  
    - **Fix pattern:** Add a visually hidden or adjacent `role="status"` / `aria-live="polite"` element whose text updates with `translateLoading`, `ttsLoading`, and completion.

11. **“Form to Complete”: required rule not indicated until submit**  
    - **Where:** `components/features/document/ExtractedDataPanel.tsx` — all fields must be filled (`handleSubmit` validation) but inputs lack `required` or `aria-required="true"` and no visible “required” indicator.  
    - **WCAG:** [3.3.2 Labels or Instructions](https://www.w3.org/WAI/WCAG21/Understanding/labels-or-instructions.html) (Level A).  
    - **Fix pattern:** Mark each field `required` (and/or `aria-required="true"`), add visible “(required)” in `Label`, and keep `aria-describedby` linking to the validation alert (already partially implemented for invalid state).

12. **Desktop home layout: no `<main>` landmark**  
    - **Where:** `app/page.tsx` desktop branch — outer `<div>`, content split across branding column and form column without wrapping the primary task in `<main>`.  
    - **WCAG:** [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html).  
    - **Fix pattern:** Wrap the primary upload workflow (right column or full width on small screens) in `<main>`; optional `<aside>` for marketing column.

13. **`components/ui/sonner.tsx` — Toaster not mounted in app tree**  
    - **Where:** No `Toaster` import in `app/layout.tsx` (grep shows only the component file).  
    - **WCAG:** If toasts are used later without a live region host, [4.1.3 Status Messages](https://www.w3.org/WAI/WCAG21/Understanding/status-messages.html) fails.  
    - **Fix pattern:** Mount `<Toaster />` in root layout; Sonner provides live regions by default — verify after integration. Ensure `next-themes` `ThemeProvider` wraps the app if `useTheme()` must not throw.

14. **Language selector: visible group label not programmatically tied to selects**  
    - **Where:** `components/shared/LanguageSelector.tsx` — “Translation direction” is a `<p>`, not `<fieldset>` + `<legend>` or `aria-labelledby` on the `Select` triggers.  
    - **WCAG:** [1.3.1 Info and Relationships](https://www.w3.org/WAI/WCAG21/Understanding/info-and-relationships.html).  
    - **Fix pattern:** Use `<fieldset className="…">` + `<legend className="…">Translation direction</legend>` around the row, or `aria-labelledby` referencing an `id` on the legend paragraph.

### Low Severity (enhancement)

15. **Root `lang` is fixed to English**  
    - **Where:** `app/layout.tsx` — `<html lang="en">`.  
    - **WCAG:** [3.1.1 Language of Page](https://www.w3.org/WAI/WCAG21/Understanding/language-of-page.html).  
    - **Fix pattern:** When UI locale routing exists, set `lang` dynamically; for embedded user content in another language, use `lang` on the wrapping element.

16. **Progress bar without accessible value text**  
    - **Where:** `ExtractedDataPanel` — `<Progress value={…} />` during job processing.  
    - **WCAG:** [1.1.1 Non-text Content](https://www.w3.org/WAI/WCAG21/Understanding/non-text-content.html) (informative progress).  
    - **Fix pattern:** Add `aria-label` / `aria-valuenow` / `aria-valuemin` / `aria-valuemax` if the primitive does not already map them (Radix Progress usually does — verify in `components/ui/progress.tsx` when used).

17. **`ItemActions` with lone `ExternalLinkIcon`**  
    - **Where:** `DetectTab.tsx` — icon in actions column while the link may live in the title/description.  
    - **Fix pattern:** If decorative, `aria-hidden="true"` on the icon; if implying “opens externally”, expose text via `sr-only` or `aria-label` on a parent link.

18. **Download link filename**  
    - **Where:** `TtsPlaybackVisual.tsx` — `download="translated-audio"` is generic.  
    - **Fix pattern:** Prefer a filename derived from session/document id or user filename for clarity (not strictly WCAG failure).

19. **Read-along active word styling**  
    - **Where:** `globals.css` — `.tts-readalong-word-active` uses background, color, and underline.  
    - **Note:** Multiple visual channels reduce “color alone” risk ([1.4.1 Use of Color](https://www.w3.org/WAI/WCAG21/Understanding/use-of-color.html)). Optional: add `aria-current="true"` on the active word `span` for screen reader context (test verbosity).

20. **Dialog / tabs primitives (Radix)**  
    - **Where:** `components/ui/dialog.tsx`, `tabs.tsx`, `select.tsx`, `radio-group.tsx`.  
    - **Note:** Radix generally provides `role="dialog"`, focus trap, `aria-modal`, and tab roles. **Verify** after upgrades that `DialogTitle` / `DialogDescription` remain present (they are used correctly on the translate read-aloud dialog). Close button uses `sr-only` “Close” — good.
