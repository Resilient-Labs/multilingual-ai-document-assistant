# Accessibility audit — Chunking pipeline + upload wiring

**Scope:** `components/upload-form.tsx` (primary), with context from `components/ui/select.tsx`, `components/ui/button.tsx`, `components/ui/spinner.tsx`, `app/globals.css`.

**Standard:** WCAG 2.1 AA (per role checklist).

---

## Findings

```
// 🔴 [A11Y] WCAG 4.1.2 / HTML: Nested interactive elements — dropzone root from react-dropzone uses role="button" (via getRootProps) while the same region contains native <button> / <Button> controls ("Browse files", "Take photo", "Remove file").
//    Fix: Avoid button-inside-button for assistive tech and valid focus paths. Options: (a) pass getRootProps({ role: 'presentation' }) or role="group" only if you remove keyboard activation from the container and wire file dialog to an explicit control; (b) prefer useDropzone’s open() on the visible "Browse files" / "Take photo" button and use <label htmlFor={inputId}> tied to the hidden file input; (c) see react-dropzone guidance for nested controls (override root role, no nested buttons). Ensure one clear keyboard target to open the picker and separate controls for remove.
```

```
// 🟡 [A11Y] WCAG 3.3.1 / 4.1.3: Errors are surfaced only with window.alert(), which interrupts flow, can steal focus unpredictably, and is weaker than in-page status patterns.
//    Fix: Render errors in a dedicated region with role="alert" or aria-live="assertive"/"polite", associate with the form via aria-describedby, and move focus to the first error or the summary (manage focus explicitly). Reserve alert() only as a last resort.
```

```
// 🟡 [A11Y] WCAG 1.3.1: The visible heading text "Translation direction" is a plain <p>; it is not programmatically grouped with the two language <Select> triggers.
//    Fix: Wrap source/target controls in <fieldset> with <legend className="...">Translation direction</legend>, or give the section an id and set aria-labelledby on a wrapping element that contains both selects; optionally add visually hidden text on each trigger if you need redundant context.
```

```
// 🟡 [A11Y] WCAG 3.3.2 / 4.1.3: While submitting, the submit control shows only a spinner; disabled state is not explicitly exposed on the form, and there is no polite status announcement for the overall operation.
//    Fix: On the <form>, set aria-busy={isSubmitting}. Keep visible text (e.g. "Translating…") next to the spinner, or set aria-label / aria-labelledby on the submit <Button> when loading (e.g. aria-label="Translating document, please wait"). Optionally add a visually hidden aria-live="polite" node that updates when submission starts/ends.
```

```
// 🔵 [A11Y] WCAG 1.1.1 / best practice: Decorative Lucide icons (e.g. FileTextIcon, UploadCloudIcon, CameraIcon next to visible text, ArrowRightLeftIcon inside an already labelled swap button) are exposed as vector graphics without aria-hidden.
//    Fix: Pass aria-hidden="true" on decorative icons; keep aria-label only on icon-only controls (swap and remove already have labels — good).
```

```
// 🔵 [A11Y] WCAG 1.3.1 enhancement: The custom dropzone could expose a concise accessible name and accepted types for the root control (especially when the visible copy is long).
//    Fix: Merge getRootProps({ 'aria-label': 'Upload document. Accepted: PDF, Word, text, images. Maximum size 10 megabytes.' }) (adjust string to match product copy), or aria-describedby pointing to static hint text id.
```

```
// 🔵 [A11Y] Consumed primitive note (Select listbox items): components/ui/select.tsx SelectItem uses outline-hidden with background-only focus styling; verify focus visibility and non-text contrast (2.4.7 / 1.4.11) against your theme tokens in all themes.
//    Fix: If focus is too subtle, add focus-visible:ring-* (matching SelectTrigger) alongside focus:bg-accent on SelectItem, and verify in forced-colors / high-contrast modes.
```

---

## Positive observations

- Swap and remove controls use real `<button type="button">` with `aria-label` for icon-only actions.
- Submit actions use a native submit `<Button type="submit">` with a logical label when idle.
- `Spinner` uses `role="status"` and `aria-label="Loading"`, which helps when used as the sole loading indicator (still pair with explicit button/form semantics as above).
- `Select` triggers use the shared focus-visible ring pattern (`focus-visible:ring-*`) from the UI kit.
- Drag-active state on desktop is not color-only: the primary instruction string changes ("Drop your file here" vs default).
- Global `*` base styles include `outline-ring/50`, which supports focus visibility when the UA outline is used (verify for the dropzone container and any custom resets).
