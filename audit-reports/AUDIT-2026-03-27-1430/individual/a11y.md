## Findings (`upload-form.tsx`)

### 🔴 High

```
// 🔴 [A11Y] WCAG 4.1.3 (Status Messages, AA): Dynamic error text is not exposed as a status message.
//    When `error` is set after a failed submit, sighted users see the destructive-styled box, but
//    assistive technologies are not reliably notified without a live region or alert role.
//    Fix: On the error container, add role="alert" (assertive) or aria-live="assertive" (and
//    ensure the node is present in the DOM when empty vs. mount when error is set). Example:
//    <div role="alert" className="...">{error}</div> or a single region with aria-live="polite"
//    for non-critical messages. Pair with aria-relevant="additions text" if content replaces.
```

---

### 🟡 Medium

```
// 🟡 [A11Y] WCAG 1.3.1 / 4.1.2 (Name, Role, Value): Source and target language selects are not
//    programmatically distinguishable beyond their current values. Both triggers expose similar
//    semantics (e.g. two “combobox” controls showing language names); layout conveys “left = source”
//    but that spatial cue is weak for screen reader users.
//    Fix: Give each SelectTrigger an explicit accessible name, e.g. aria-label="Source language"
//    and aria-label="Target language", or wrap the pair in <fieldset><legend>Translation direction</legend>
//    and use aria-labelledby pointing to stable ids for each trigger. Ensure names don’t duplicate
//    the visible value in a confusing way (Radix merges label + value appropriately).
```

```
// 🟡 [A11Y] WCAG 3.3.1 / 4.1.3: OCR / upload progress strings (`ocrProgress`, percentage updates)
//    are shown as the submit button label while idle text path exists, but during `isSubmitting` the
//    button content is replaced by <Spinner> only. Screen reader users lose the detailed progress
//    (e.g. “Recognizing… 42%”) that sighted users saw before the swap, and ongoing updates are not
//    announced.
//    Fix: Add a visually hidden or polite aria-live region that mirrors `ocrProgress` while submitting,
//    e.g. <p className="sr-only" aria-live="polite" aria-atomic="true">{ocrProgress}</p>. Keep the
//    button with aria-busy="true" during submission. Optionally keep concise visible text + spinner
//    together so the accessible name stays informative.
```

```
// 🟡 [A11Y] WCAG 2.1.1 / 2.4.3 (Focus Order): Mobile empty state nests a focusable <Button> (“Take photo”)
//    inside the dropzone root that also receives dropzone root props (often including tabIndex and
//    click-to-open behavior). Users may encounter two tab stops for the same “choose file” action.
//    Fix: Prefer a single primary control: e.g. make the inner control open the file dialog via
//    dropzone’s `open` API with type="button", or remove keyboard focus from the outer container
//    when a dedicated button is present (override getRootProps tabIndex / noKeyboard as appropriate
//    per react-dropzone version). Verify with keyboard-only traversal.
```

```
// 🟡 [A11Y] WCAG 2.1.1 (Keyboard) — verify: Custom dropzone root is a <div> with react-dropzone props.
//    Ensure the installed react-dropzone version forwards keyboard activation (Enter/Space) to open
//    the file dialog and exposes a focusable root where intended. If not, add explicit keyboard
//    handlers and role="button" + tabIndex={0} only if you cannot use a native <label htmlFor>
//    pointing at the hidden file input pattern.
//    Fix: Audit getRootProps() in your lockfile version; document or patch gaps; prefer native
//    labeling + visible “Browse files” that triggers input.click() with full keyboard support.
```

## Positive notes

- Icon-only controls **Swap languages** and **Remove file** include **`aria-label`**, satisfying name requirements for non-text buttons.
- **Submit** uses the shared **`Spinner`**, which sets **`role="status"`** and **`aria-label="Loading"`**, giving a basic busy state when the spinner is shown.
- **Semantic `<form>`** and **`type="button"`** on auxiliary actions reduce accidental submission.
- **Disabled swap** when source is **Detect language** is consistent with **`disabled`** and avoids misleading actions.
- **Drag-active** state is not conveyed by color alone; primary instruction text changes (e.g. “Drop your file here”).
- **shadcn `Button` / `SelectTrigger`** use **`outline-none`** with **`focus-visible:ring`** replacements (see `components/ui/button.tsx`, `components/ui/select.tsx`), supporting **2.4.7 Focus Visible** when those primitives are used as intended.
